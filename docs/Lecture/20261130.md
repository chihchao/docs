# 科技創新趨勢與需求探索

## 人工智慧應用開發基礎（2）提示詞

### 知識庫問答機器人

```markdown
以 GAS 網頁應用程式建立聊天網頁，串接 Gemini API 及建立的 File Search 知識庫，讓聊天機器人能依據自有文件回答問題，並標示答案出自哪份文件。
- 聊天介面：建立聊天網頁，含訊息顯示區、輸入框與送出按鈕，並區分使用者與機器人的訊息樣式。
- 系統提示詞：【使用 kawaii style 的陪伴聊天機器人和我對話】
- 模型：gemini-3.5-flash-lite
- 安全：API Key 和 Store ID 存於指令碼屬性。
- 文件引用：回答下方列出引用的文件名稱與片段。請在回答的最下方加上分隔線，列出「參考的文件名稱」以及「一小段原文摘要」（約 50 字以內就好），重複的文件名稱請合併顯示。
- 範圍控制：以系統提示詞要求優先依據知識庫回答；文件查無相關內容時，需明確告知，不可憑空編造。
- 對話記憶與錯誤處理：保留前幾輪對話；Store 不存在或呼叫失敗時顯示友善提示。
```

### Line Bot

#### 知識庫回答

```markdown
請幫我寫一份 Google Apps Script 程式碼，用來做為 LINE 聊天機器人的後端，讓它能連接 Gemini AI 與我建立好的知識庫（File Search）來回答問題。
請符合以下需求：
1. 金鑰與設定管理
   - 將「Gemini API 金鑰」、「知識庫名稱（Store ID）」與「LINE 機器人權杖（Channel Access Token）」這三個設定值，統一放在 GAS 的「指令碼屬性」中管理，不要直接寫死在程式碼裡。
2. LINE 聊天機器人基本互動
   - 當使用者傳送文字訊息時，自動查詢知識庫並回覆答案。
   - 在等待 AI 思考與查詢資料期間，讓 LINE 聊天室顯示「對方正在輸入中...」的載入動畫，提升使用體驗。
   - 如果使用者傳送貼圖、圖片或語音等非文字訊息，請用可愛的語氣提醒他改用文字發問。
3. AI 角色與知識庫問答規則
   - 使用模型：gemini-3.5-flash-lite
   - 說話風格：使用可愛、親切、帶點賣萌感（kawaii style）的陪伴型機器人語氣，適度加上可愛的表情符號或顏文字。
   - 回答範圍限制：必須優先且嚴格依據知識庫裡的文件來回答。如果文件裡找不到相關內容，請用可愛但明確的語氣告訴使用者「知識庫裡還找不到這題的資料喔」，絕對不可以憑空編造或自己猜測答案。
4. 對話記憶功能
   - 讓機器人能記住每位使用者最近多輪的對話內容（大約保留 30 分鐘），這樣使用者才能接著追問（例如問完 A 之後，接著問「那它的費用是多少？」）。不同使用者的對話紀錄要分開計算，不能混在一起。
   - 設定一個清除指令：當使用者輸入「清除記憶」或「重新開始」時，就清空他目前的對話紀錄並回覆確認。
5. 錯誤處理與教學說明
   - 如果發生知識庫找不到、連線逾時或系統忙碌等狀況，不要讓機器人沒反應，請回傳一句可愛的錯誤提示（例如：「哎呀，腦袋暫時打結了，請稍後再問我一次喔！」）。
   - 請提供完整的程式碼，並在最後用白話步驟教我如何把這段程式碼部署上線，以及如何綁定到 LINE 官方帳號。
```

#### 具呼叫程式執行的知識庫回答
